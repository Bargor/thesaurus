# Household observation ownership

`HouseholdObservation.observe` is a cold flow: every collector owns an independent group of repository listeners. A ViewModel collects it once in `viewModelScope` and exposes its existing `StateFlow` to screens and other UI consumers. Reusing that StateFlow does not create additional Firestore listeners. Cancelling the collector, clearing the ViewModel, switching household/account, or retrying disposes the group's child listeners. There is no global cache shared between households or accounts.

Subcategory listeners are keyed by category ID. The required keys are the union of current taxonomy, nondeleted entries' historical category IDs, and explicitly supplied historical IDs. Renames, archival, category order changes, and metadata-only snapshots update the model without restarting unchanged keys. Removed keys lose their listeners, values, and errors. A cancelled listener cannot restore its removed cache.

`ObservedSource` separates the first-observation loading state, a successfully loaded empty collection, and a missing value. It retains the last good value alongside the latest observation's typed sync state and error. Equal values retain their reference so screen aggregation caches need not recompute for metadata changes. The shared reducer gives errors priority over pending writes, then offline/cache observations, then synchronized observations.

Summary, Browse, and Reports may pass their last read model as a retry seed. A seed is accepted only when its household, actor identity, and enabled-source subscription configuration exactly match the new subscription. Switching identity or changing the subscribed sources resets immediately, so disabled sources cannot contribute stale errors. A successful absent category-order preference clears an older preference; errors retain the last good preference. Entries and historical taxonomy remain available after read errors, with their latest error visible to consumers.

Balance consumers deliberately apply stricter financial rules than the general read model. The global account balance clears its number on ledger/household failure or a successfully missing household. Reports hides its absolute balance trend on ledger/household errors and does not infer an opening balance from an unavailable household. Neither may silently present a missing/error balance as zero. Signed ledger values, opening-balance settings, and all-history balance calculations remain independent of screen filters, taxonomy ordering, and presentation helpers.

Entry form taxonomy uses a taxonomy-only listener group. Its initial taxonomy publication waits for the category/order observations and every required subcategory listener's first observation, preserving restored IDs while sources are delayed. Entry list initialization additionally waits for entries and members. Optional disabled sources do not block readiness; errors can surface immediately while other sources are still delayed. Summary, Browse, and Reports retain their entry-based loading envelope. The form's separate ledger listener owns write acknowledgement and existing-entry availability. Saved form/filter state remains owned by each ViewModel; the shared model does not edit drafts, change schema, or manage writes.
